# Ruf 0.1.0 Developer Preview

A compact, open-source SIP softphone for macOS and Windows, built with Rust,
Tauri and Svelte. This first Developer Preview is free and has no in-app purchases.

## Get started

Find native installers in the published
[GitHub Release](https://github.com/mardu-systems/ruf/releases/tag/v0.1.0).
Until a release is published, use the
[source setup](https://github.com/mardu-systems/ruf#run-locally).
The automatic source ZIP/tar archives are not desktop installers.

| Target                  | Release asset         | Acceptance boundary                                                                                        |
| ----------------------- | --------------------- | ---------------------------------------------------------------------------------------------------------- |
| macOS 14+ Apple Silicon | Native DMG            | Inspect the exact asset's signing status; provider and physical-device acceptance remain profile-specific. |
| Windows 11 x64          | Native NSIS setup EXE | Experimental; Windows Server CI compilation does not qualify Windows 11 audio or desktop behavior.         |

Each installer is accompanied by its CycloneDX SBOM and build-hash manifest.
`SHA256SUMS` covers both installers. Verify the matching hash before opening a
package; hashes do not authenticate a publisher.

Use the [tester guide](https://github.com/mardu-systems/ruf/blob/main/docs/testing-preview.md)
for installation, the first controlled call and the test matrix. Watch the
[UI demo](https://github.com/mardu-systems/ruf#ui-demo) for a sample-data walkthrough.
Help with Windows headset testing, FreeSWITCH interoperability or fresh-Mac setup;
submit a [compatibility report](https://github.com/mardu-systems/ruf/issues/new?template=compatibility_report.yml).

## Scope

Ruf is a compact SIP softphone targeting macOS 14+ on Apple Silicon and Windows 11 x64.
This preview is intended for isolated test networks: UDP/TCP and ordinary RTP are
unencrypted. Accounts can require TLS and SDES-SRTP with certificate/hostname
verification and no plaintext fallback. At most two related dialogs share one
audible conversation. Provider compatibility and real
microphone/headset operation require testing on the installed application.

## Included

- German and English phone/settings UI, menus and app-owned notification text,
  with automatic system-language selection or a saved manual choice. Native
  permission-purpose resources and Windows installer strings include both languages.
- Up to eight saved SIP accounts with independent registration and outgoing
  account selection. Accounts can be disabled without deleting credentials or
  silently switching outgoing identity. Passwords use macOS Keychain / Windows
  Credential Manager; explicit reconnect supports credential-access recovery.
- Incoming/outgoing calls, answer, reject and hangup; typed registration and call
  errors, background ringing, tray controls and actionable notifications.
- Native mute, confirmed hold/resume, blind transfer and consultation with switching,
  cancellation and attended transfer. Unsolicited incoming REFER is rejected.
  An expandable in-call keypad sends native DTMF, including star/hash IVR input.
- Eight settings sections with concrete field search, protected drafts, keyboard
  focus, account-specific accessible action names and long-name wrapping.
- Combined action, authorized-contact and local-history search with Cmd+K on
  macOS or Ctrl+K on Windows. Results open existing details; choosing a contact
  or history result never dials automatically. Native menus and window-local
  shortcuts reuse the existing guarded call controls.
- Separate microphone, speaker and ringtone routing; classic/soft/short ringtones
  and ringtone-only volume. Explicit native microphone metering runs for at most
  ten seconds, and a speaker test for two seconds. Real calls preempt audio tests.
- Independent notification, microphone and contact permission checks. OS prompts
  require explicit actions; saving the notification switch never requests access.
  Anonymous delayed test notifications and optional caller-detail hiding help
  check background notifications without creating a fake call.
- Login-only hidden-start preference; manual opening still shows the phone.
- Authorized macOS contact search, favorites and direct dialing. Windows contact
  integration is not available. Favorites-first ordering and organization labels
  are configurable.
- Formatted telephone numbers accept a leading plus and visual separators.
  Authorized contacts provide dial suggestions and current names in conversations,
  notifications and older history. German national/international number matching
  is configurable and never rewrites the dialed number.
- Local SQLite call history with results, duration, search and callback through
  the original account. Recording can be disabled for future calls while retaining
  prior rows. Completed entries can expire after 30/90/365 days; unlimited retention
  remains the default. Shortening that would delete rows requires confirmation.
- Local health diagnostics with an explicit preview/copy action and a whitelist
  excluding personal account, caller and contact details.
- About page with bundled changelog, license texts and a build-specific dependency
  inventory in CycloneDX format. A configured public GitHub changelog can refresh
  the notes on demand, with bundled notes retained on failure; no source is
  configured automatically from the Git remote.

## Existing installations

Password-free account/settings metadata uses schema version 2. Existing version-1
files load with compatibility defaults; the exact original bytes are backed up
before the first replacement. Credential keys and outgoing selection remain
intact. Disabled accounts restore without reading passwords or creating native
user agents. See [preferences and migration](https://github.com/mardu-systems/ruf/blob/main/docs/api/preferences.md) and
[account activation](https://github.com/mardu-systems/ruf/blob/main/docs/api/account-activation.md).
An edit with an empty password keeps the saved credential and its key; an explicit
replacement password uses the existing journaled rotation/cleanup path. A fresh
Ruf installation starts with empty account fields and no preconfigured lab account.
Metadata belonging to a different bundle identifier is not imported automatically.

## Verification boundaries

Local macOS verification covers UI/browser regressions, native state/audio
ownership tests, isolated Asterisk SIP/RTP scenarios, and signed bundle metadata.
A recent local installation/start check also confirmed the installed executable
matched its build and the phone window appeared. These checks do not establish
real notification banners, hardware microphone/speaker behavior, provider
compatibility or Windows runtime. See the
[settings verification](https://github.com/mardu-systems/ruf/blob/main/docs/verification/2026-11-05-settings-redesign.md) and
[UI regression summary](https://github.com/mardu-systems/ruf/blob/main/docs/verification/README.md#desktop-ui-and-local-data), plus
[native call controls and security](https://github.com/mardu-systems/ruf/blob/main/docs/verification/2026-11-05-call-controls-security.md).
The [10 November local release checks](https://github.com/mardu-systems/ruf/blob/main/docs/verification/2026-11-10-release-checks.md)
include fresh Asterisk, synthetic OS-keychain integration and separately hashed
portable/native macOS packages. They do not establish platform/provider acceptance
for every published installer. Hosted results for each revision are available in
the [GitHub CI workflow](https://github.com/mardu-systems/ruf/actions/workflows/ci.yml).
The Windows build runner uses Windows Server 2022; it does not qualify Windows 11
desktop or physical audio behavior.

Microphone authorization metadata is currently implemented on macOS. Other
platforms report unsupported metadata; explicit microphone tests rely on native
capture succeeding. Windows contacts remain unavailable. Caller-details hiding
applies to OS notification text, not the phone window or retained history.

## Distribution status

Default direct-distribution builds use ad-hoc signing on macOS; Windows installers
are unsigned. Local Developer ID App/DMG signing has been observed separately;
notarization has not. That local result does not establish signing of hosted
assets. Record the exact signing/notarization status beside each published installer.
Windows publisher signing and automatic updates are not configured.
Calendar integration is not implemented. The generated inventory
requires review against the shipped variant and is not a compliance attestation.
Separate macOS App Store preparation scripts and a sandbox configuration exist;
they do not configure Developer ID distribution, upload a build or establish App
Review approval. See [App Store preparation](https://github.com/mardu-systems/ruf/blob/main/docs/release-checklist.md#mac-app-store-preparation).

The workflow creates a draft prerelease only after quality, native build/test and
Asterisk SIP/RTP jobs pass. It attaches one DMG, one NSIS installer, the matching
SBOM/build-hash manifests and SHA256SUMS for the installers.
To verify downloaded installers in the same directory, run `sha256sum -c SHA256SUMS`
(macOS: `shasum -a 256 -c SHA256SUMS`). Checksums detect changed downloads; they do
not replace publisher signing. Hosted builds do not establish Windows runtime,
hardware audio, notification interaction or provider compatibility.
