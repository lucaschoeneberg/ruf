# Ruf 0.1.1 Developer Preview

A compact, open-source SIP softphone for macOS and Windows, built with Rust,
Tauri, Svelte and native baresip calling. This Developer Preview is **free**, with
**no in-app purchases**. It is intended for isolated test networks.

## Download and try it

Download the native installers from this release's assets:

| Platform                   | Installer              | Distribution status                                                                       |
| -------------------------- | ---------------------- | ----------------------------------------------------------------------------------------- |
| macOS 14+ on Apple Silicon | DMG containing Ruf.app | Ad-hoc signed; not notarized. Intel Macs are not a supported target.                      |
| Windows 11 x64             | NSIS setup EXE         | Unsigned; experimental until installed desktop and physical-audio acceptance is recorded. |

Each target includes a CycloneDX SBOM and build-hash manifest. Download
`SHA256SUMS` alongside the installers. On macOS, with both listed installers in
the same directory, run `shasum -a 256 -c SHA256SUMS`. On Windows, run
`Get-FileHash -Algorithm SHA256 .\<installer>.exe` and compare the result with its
matching line. Checksums detect changed downloads; they do not authenticate the
publisher. The source ZIP and tar archives are not desktop installers.

Read the package's signing status before opening it. Do not disable operating
system protection to run an untrusted package. If it cannot be opened under your
system policy, use the documented source build in a controlled development setup.

Follow the [tester guide](https://github.com/mardu-systems/ruf/blob/v0.1.1/docs/testing-preview.md)
for account setup, audio routing and the first controlled two-way call. Ruf needs
an existing SIP test account or PBX; it does not supply telephone service. Watch
the [UI demo](https://github.com/mardu-systems/ruf/tree/v0.1.1#ui-demo), which uses
synthetic data and does not demonstrate a live call.

## Included in this preview

- German and English phone/settings UI, native menus and app-owned notification
  text, with automatic system-language selection or a saved manual choice.
- Up to eight saved SIP accounts with independent registration and outgoing
  identity. Credentials use macOS Keychain or Windows Credential Manager.
- Incoming/outgoing calls, native mute, hold/resume, DTMF, direct transfer and
  attended transfer through a consultation. Two related dialogs share one audible
  conversation.
- Separate microphone, call-speaker and ringtone outputs; bounded audio tests,
  background/tray operation, keyboard shortcuts and action search.
- Authorized macOS contacts and local call history. Windows contacts, calendar
  integration and automatic updates are not available.
- Current repository media, a tester guide and a compatibility-report form.
  Platform-specific menu compilation and synthetic localization polling were
  corrected during release preparation.

See the [full feature scope](https://github.com/mardu-systems/ruf/blob/v0.1.1/docs/releases/0.1.0.md)
and [user-facing changelog](https://github.com/mardu-systems/ruf/blob/v0.1.1/CHANGELOG.md).
Existing account metadata and credential keys retain the same app identity; this
release does not introduce a new account schema or automatic updater.

## Verification and limits

The release workflow gates its draft on portable/UI checks, native macOS and
Windows builds/tests, and isolated Asterisk SIP/RTP interoperability. Each
installer, SBOM and manifest comes from that same tagged workflow run. Workflow
results are available in [GitHub Actions](https://github.com/mardu-systems/ruf/actions/workflows/release.yml).

Automated calling and synthetic audio tests do not qualify real microphones,
headsets, OS notification interaction, arbitrary providers or Windows 11 desktop
behavior. The Windows build runner is Windows Server 2022. Installed-platform,
physical-audio, FreeSWITCH and provider acceptance remain open; this is not a
supported production release.

UDP/TCP signaling and ordinary RTP are unencrypted. Accounts can require verified
TLS and SDES-SRTP with no plaintext fallback. Per-call observations do not
establish end-to-end encryption. See [account security](https://github.com/mardu-systems/ruf/blob/v0.1.1/docs/api/account-security.md).

Help test Windows audio, FreeSWITCH or first-run setup with the
[compatibility form](https://github.com/mardu-systems/ruf/issues/new?template=compatibility_report.yml).
Use synthetic identities and omit credentials, personal numbers, contact lists
and raw SIP/SDP captures. Report security-sensitive issues through
[SECURITY.md](https://github.com/mardu-systems/ruf/blob/v0.1.1/SECURITY.md).

Own code is MIT licensed; dependencies retain their upstream licenses. The SBOM
is a build inventory, not a compliance attestation. See
[third-party notices](https://github.com/mardu-systems/ruf/blob/v0.1.1/THIRD_PARTY_NOTICES.md).
