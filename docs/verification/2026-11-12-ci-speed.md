# Native CI speed — 12 November 2026

Local observations on macOS arm64, working tree based on `83277b9`, using its
unchanged baresip/libre 4.12 SDK, OpenSSL 3.5.9 and pinned Rust/Bun versions.
This change is independent of the SIP upgrade and workspace-maintenance PRs.

## Changes and measurements

The desktop workflow keeps the complete SDK cache and adds an exact, independent
OpenSSL cache. macOS stores the static install, keyed by the extracted build
recipe; Windows stores the existing vcpkg install, keyed by its manifest/helper.
Both retain target/compiler/image identity, existing SDK qualification and
non-PR-only cache writes. SIP pins/patches no longer invalidate OpenSSL itself.
The shell recipe preserves the prior checksum, flags and full OpenSSL test command.

The native runner discovers actual compiled test names. All NAT tests and named
SIP timeout cases run separately, ordinary SIP tests remain serial, and all other
workspace/integration/doc tests remain covered. At most six processes run at once;
blackout/long-hold cases start first. Protocol timers and test assertions do not
change. Stdout/stderr, including partial lines, stream with process prefixes;
failure retains raw logs and waits for every child and reader before returning.

Sequential local runs on the same SDK:

| Measurement                                   | Original runner | New runner           |
| --------------------------------------------- | --------------- | -------------------- |
| Total command time, including build/discovery | 318.09 s        | 135.95 s             |
| Longest test partition                        | 293.6 s         | 131.7 s              |
| Tests passed / failed / ignored               | 312 / 0 / 20    | 312 / 0 / 20         |
| Test processes                                | 3               | 17, at most 6 active |

The critical test partition was about 55% shorter. The original total included
more compilation, so its 57% overall reduction is not a pure scheduling measure.
The new run overlapped an OpenSSL build/test attempt. These are local observations,
not a hosted runtime guarantee. GitHub runner availability and cold compilation
still affect total CI time. An independent OpenSSL cache must first be populated
by a qualifying non-PR run; no hosted restore/save result is claimed here.

## Verification

- Actionlint v1.7.12 accepted all workflows; Bash syntax check accepted the recipe.
- Child-process fixtures proved exact-once discovery coverage, bounded parallelism,
  immediate partial stdout/stderr, failure aggregation, retained logs, and rejection
  of empty native discovery. Reader/log failure exposed live children at return
  before correction; the regression passed after kill-and-await cleanup.
- Original and new complete native workspace suites passed as recorded above.
- Portable workspace tests, portable/native Clippy with warnings denied, tooling/
  Svelte checks, frontend build, version/format checks and unchanged generated DTOs
  passed. UI suite includes the process fixtures.
- Asterisk echo plus all 30 existing interop/security/startup checks passed.
- Native macOS app build passed; existing LLVM debug-stripping and unsigned/
  non-notarized preview limitations remain. No installation/publication occurred.
- The extracted OpenSSL recipe downloaded and checksum-verified the pinned source
  and compiled it successfully. Fresh static archives/headers passed the existing
  CMake probe, including macOS-14 object minimums and resolved version 3.5.9.

The complete local OpenSSL suite was **not qualified**: unchanged upstream
`82-test_ocsp_cert_chain.t` deadlocked on this macOS 27.2 host. Sampling showed
`s_server` blocked writing its OCSP response while Perl waited for `s_client`,
which waited for the server handshake. Only those four confirmed fixture
processes were terminated; make returned failure. The full test command is
retained, without skips, and must pass in hosted CI before cache qualification.
Windows execution and actual hosted cache hits remain unverified locally.

Independent review found the output-error lifecycle issue above; its fix and
regression were applied. Existing native APIs/DTOs, SIP/audio code, dependencies
and locks are unchanged. Tool behavior is documented in `docs/api/tooling.md`;
cache behavior is documented in `docs/ci-cd.md` and `native/README.md`.
