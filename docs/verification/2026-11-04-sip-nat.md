# Client-side SIP NAT handling

## Implemented behavior

The pinned libre SDK now learns a local UDP address mapping from a successful
REGISTER response matched to its transaction, source peer, actual local socket,
Call-ID, transmitted CSeq and echoed Via. Only valid numeric unicast received
addresses with matching address family and decimal rport 1–65535 are accepted.

The mapping is scoped to the SIP instance and exact local/peer IP+port tuple.
Contact and request Via serialization use it; actual socket addresses, the
registration local address used for media, RTP binding and remote dialog targets
are preserved. A changed mapping causes a new REGISTER with the obsolete Contact
at expires=0 and the mapped Contact before registration success is reported.
Two immediate mapping corrections are allowed per fresh cycle; instability uses
normal failure backoff and a subsequent fresh cycle can recover. Storage is
bounded to 32 live tuples, with negotiated-expiry-based lifetimes and reusable
expired slots.

No Tailscale, router, firewall or real UniFi Talk setting was changed. The only
PBX configuration edits were synthetic accounts in the isolated Asterisk lab.
Telephone's public source was used as a behavioral reference; no Telephone or
PJSIP code/dependency was imported.

  `docs/api/README.md`, `tests/interop/asterisk/README.md`: contracts, provenance,

## Verification

- Before the fix, the new Asterisk no-rewrite regression failed after 15 seconds
  with registration `registered` and call `active` after the PBX had hung up.
- With the final native patch, that test passed in 3.28 seconds: outgoing remote
  termination, incoming answer/remote termination, and a subsequent call, without
  issuing local hangup.
- SDK `test_sip_nat` passed: invalid/failed/mismatched responses, numeric port and
  address validation, peer/socket isolation and bounded mapping storage.
- SDK `test_sip_nat_registration` passed: real UDP registration, CSeq handling,
  port-only translation, old Contact removal, correct expiry among multiple
  bindings, retry cap, backoff and recovery on a fresh registration cycle.
- `bun run test:asterisk` passed all four native interop tests. RTP echo returned
  4.04 seconds of mono PCM16 at 8 kHz, RMS 5811 and 439.8 Hz. This verifies that
  mapped signaling did not break native media binding; it uses synthetic audio.
- `bun run test:sip-diagnostics` passed with 60 allowlisted markers, a transmitted
  200 response to remote BYE and no raw SIP headers/passwords; disabled by default.
- Native workspace Clippy with warnings denied and Cargo tests passed.
- Independent scoped review found integration issues in the first patch draft;
  those were fixed and covered by the real registration test. Follow-up review
  found no remaining blocking issue.

## Limits

This is SIP/UDP signaling adaptation, not media ICE/TURN, SIP encryption or
support for all registrar/proxy/NAT topologies. Unencrypted SIP response matching
is not cryptographic server authentication. Windows runtime and hosted CI have
not been executed here. The real UniFi Talk/Tailscale remote-hangup signaling
acceptance result is recorded below. No real account was used to initiate an
automated external call.

Additional completed checks: format/version checks, 11 frontend tests,
Svelte/TypeScript checks, frontend production build, portable workspace Clippy
and Cargo tests. Regenerated frontend contracts were byte-identical. Native
macOS arm64 `.app` build succeeded and its signed microphone entitlement/purpose
check passed. The local toolchain emitted existing rust-objcopy/libLLVM and
OpenSSL minimum-OS warnings; no new dependency or platform certification is
implied. The verified app was copied to ignored `native/build/nat-fix/SIP.app`
and launched with restricted diagnostics after the old app exited cleanly.

## User-operated UniFi Talk/Tailscale acceptance

The user tested the rebuilt native app with the adaptive audio profile. In both
captured call sequences, the restricted trace records received BYE, transmitted
200 OK with CSeq method BYE, and native close-event dispatch. No local transmitted
BYE appears in this session. This confirms successful remote-termination SIP
signaling through the real deployment, where the previous builds recorded no
remote BYE and repeated local BYE retransmissions.

Outgoing INVITE Contact is now categorized as private and differs from the local
tunnel socket address, consistent with the learned local NAT mapping.
`contact-match=no` is expected in this situation; it is not a failed SIP request.
The callback marker records native dispatch, not independent proof that the
webview consumed the state or a measurement of UI update delay. No personal
numbers, actual addresses, SIP headers or audio are included here.
