# Ruf v0.1.1 release verification · 11 November 2026

The user authorized the remaining release checks, necessary fixes and public
v0.1.1 publication. The tagged source revision is
`640ae23d11153ab1a9878a591a51e27d7a6dfc6e`. Results below are bound to that
revision and its workflow assets, not arbitrary later 0.1.1 packages.

## Change and local verification

- Synchronized `package.json`, `apps/desktop/package.json`, the Cargo workspace
  version and tool-generated lockfiles. Only local package versions changed;
  external dependencies were not added or upgraded.
- Added `docs/releases/0.1.1.md` and matching DE/EN changelog entries; refreshed
  README, tester/distribution documentation and synthetic repository media.
- Reused the existing media fixture and manifest rather than introducing a new
  capture pipeline. `scripts/capture-repository.ts` now takes the version from
  the root package manifest and passes it into the self-contained fixture.
  Its command documentation is maintained in `docs/api/tooling.md`.
- Reproduced a changelog test failure caused by its fixed 0.1.0 first-entry
  expectation. The test now checks the current root version in both languages,
  checks corresponding change counts and retains its historical-content check.
  No assertion was removed to bypass a functional failure.
- No production SIP/audio implementation, IPC command, DTO or account schema
  changed. Existing build, inventory, native and browser patterns were reused.

## Remaining qualification boundaries

This is a free Developer Preview with no in-app purchases. The exact macOS asset is ad-hoc signed and not notarized; the Windows installer is unsigned. Real Windows 11 desktop behavior, physical audio devices, notification interaction, macOS 14 runtime and provider/FreeSWITCH acceptance remain unqualified. CI compilation and synthetic media do not replace those checks or the supported-beta matrix. No App Store submission was made.

The frontend build retains its existing chunk-size warning. The successful draft job also reported that its pinned download-artifact action targets deprecated Node.js 20 and was forced onto Node.js 24 by GitHub; workflow validation and execution passed. No unrelated dependency or workflow change was made to hide warnings.
