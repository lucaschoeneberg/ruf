# Native milestone verification — 2026-11-04

Local host: macOS arm64. baresip/re 4.12.0 at the full commits in
`native/sources.json`; static Homebrew OpenSSL 3.5.9. Rust 1.98.1, Node 24.16.0.

Observed execution:

- Native SDK builds and repeat staging succeed on the local host.
- Real native lifecycle test initializes and shuts down three times, rejects a
  simultaneous second engine and dialing without registration, then releases
  resources. Core tests check injection rejection, password redaction, exclusive
  call reservation, registrar length without truncation and ASCII-only port syntax.
- Against the digest-pinned Asterisk 22.11.0 container: authenticated registration,
  outgoing call to extension 600, established state, rejection of second call and
  account replacement during the call, hangup and joined shutdown.
- The fresh received WAV is 8 kHz mono PCM16, 4.04 seconds, RMS approximately 5811,
  positive zero-crossing frequency approximately 439.8 Hz. The scripted acceptance
  thresholds are >=3 seconds, RMS >500 and 420–460 Hz after discarding startup.
- The initial silent recording failed this criterion. Captured SDP exposed an
  unreachable container media address; the lab endpoint now explicitly advertises
  the published loopback media address. This is a host-local fixture, not general
  NAT traversal support.
- Independent review found a stale call-action race. A real two-call regression
  reproduced it (stale hangup ended replacement call B), then passed after adding
  an internal call-generation check. Stale hangup/answer now preserve B. Both this
  test and the returned-audio test run through `npm run test:asterisk`.
- Invalid credentials fail registration safely; dialing unknown extension 999
  returns SIP 404. A subsequent fresh echo test succeeds.
- Native workspace Clippy and tests pass. Svelte/TypeScript check passes.
- A native ad-hoc-signed macOS `.app` bundle builds (approximately 14.8 MiB).
  A native DMG installer also builds (approximately 5.09 MiB).
  This is packaging evidence, not microphone permission or hardware audio evidence.

The scripted test and lifecycle suite use actual linked native libraries. They do
not substitute mock SIP responses for a call. Local build logs/recordings are
ignored under `native/build/`; reproduce via `npm run test:asterisk`.

Prepared but not observed: GitHub-hosted workflows, Windows SDK/linking/NSIS or
Windows 11 runtime, and the Linux-hosted integration job. Manual microphone,
headset/speaker, incoming call and OS permission checks remain outstanding.
No claims of other PBX/provider compatibility, full SIP coverage, public-network
NAT, TLS/SRTP, multiple accounts, contact/history persistence or production signing.
