# baresip/libre 4.13 integration — 12 November 2026

Observed locally on macOS arm64, in the working tree based on `83277b9`.
This records an uncommitted SDK integration, not a published release or hosted
CI qualification. Existing lockfile updates and concurrent cleanup-tool changes
were preserved; their implementation is outside this upgrade's review scope.

## Implementation and decisions

- baresip 4.13.0: `8a4f18c1c1b5331daa026236dcdd108deff601e8`.
- libre/re 4.13.0: `b827bcaf55a18be141ca7bcee1e22872a3a29656`.
- OpenSSL remains 3.5.9, built for macOS 14. Selected static modules and the
  adaptive 40–200 ms jitter-buffer configuration remain unchanged.
- All eight local patches apply in their existing order. Only contexts in
  `re-sip-nat.patch` and `baresip-call-controls.patch` changed; they retain the
  new upstream socket test and close-header declaration. Local policy logic did
  not change. Upstream BSD license files are byte-identical to the tracked texts.
- Existing APIs automatically use upstream SDP bounds handling, valid RTP-padding
  removal, stronger jitter adaptation and initial audio-source identity retention.
  The TX-thread helpers are private. Custom close headers and optional audio/codec
  modules have no current product requirement and were not added.
- Reused the existing SDK manifest/SBOM, native adapter, loopback SIP fixtures,
  CMake harness, Asterisk lab and jitter probe. No IPC/DTO or permission changes.

The first RTP regression failed against the prior 4.12 SDK because padding was
decoded as loud PCM. It passed after the 4.13 rebuild. Independent review then
strengthened it to send quiet nonzero PCMU, requiring at least 8,000 matching
decoded samples as well as excluding padding noise. That final test passed
separately in the native workspace configuration; player-generated underrun
silence cannot satisfy it. Valid multipart SDP after non-SDP metadata succeeds;
adjacent malformed boundaries terminate safely, followed by a successful new call.

All six jitter scenarios played 100/100 packets without insertion errors at
0, 12 and 40 ms synthetic arrival variation. First playout was 100 ms for the
fixed profile and 40 ms for the adaptive profile. These are virtual-clock buffer
measurements, not microphone-to-speaker latency or a guarantee under packet loss.

Asterisk returned 4.04 s of PCM, RMS 5811 at 440.1 Hz. Mute produced outgoing RMS
0.0 while incoming audio continued; unmute, hold/resume, transfer, DTMF and
verified TLS with required SRTP passed their existing media assertions.

to valid lengths. Windows/MSVC, Linux, macOS 14 runtime, physical microphone/
headset routing, subjective quality and real provider/VPN deployment were not
executed in this run. The retained source identity was reviewed in upstream code;
no separate physical-device stop/restart acceptance is claimed.
